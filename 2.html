1. Методика диагностики и выявление неисправностей компьютерных устройств

Сбор сведений о системе, анализ стабильности, проверка сети и оформление краткого резюме инцидента
Цель 1.1. Сбор базовой информации 1.2. Фиксация симптомов и стабильности 1.3. Проверка сетевых симптомов 1.4. Резюме инцидента

Цель

Научиться определять состояние компьютера, находить признаки неисправностей и документировать результаты проверки.

После выполнения заданий вы сможете:

  • узнать, какие комплектующие установлены в вашем ПК;
  • понять, как система сообщает об ошибках и сбоях;
  • анализировать сетевое подключение и фиксировать проблемы;
  • сделать выводы о возможных причинах неисправностей.

1.1. Сбор базовой информации

Зачем это нужно. Перед действиями важно знать конфигурацию: процессор, объём оперативной памяти, выпуск Windows, графическое устройство. Эти данные пригодятся для проверки соответствия требованиям ПО и поиска подходящих драйверов.

Шаг 1. Просмотр сведений о системе (msinfo32)

  1. Нажмите Win + R.
  2. Введите команду msinfo32 и нажмите Enter.
  3. Откроется окно «Сведения о системе» со следующими разделами:
    • Процессор (например, Intel Core i5‑10400);
    • Объём установленной памяти (RAM);
    • Версия и сборка Windows.
  4. Сделайте скриншот окна с основной информацией для отчёта.
Если данных много, разверните окно на весь экран перед созданием скриншота.

Шаг 2. Проверка компонентов мультимедиа (dxdiag)

  1. Нажмите Win + R, введите dxdiag, нажмите Enter.
  2. Если появится запрос проверки WHQL — выберите «Да».
  3. Просмотрите вкладки:
    • Система — CPU, RAM, версия DirectX;
    • Экран — видеокарта, версия драйвера, объём видеопамяти;
    • Звук — звуковые устройства и драйверы.
  4. Сделайте по одному скриншоту каждой вкладки.

Шаг 3. Проверка режима питания

  1. Откройте «Панель управления» и перейдите: Оборудование и звук → Электропитание.
  2. Проверьте активную схему:
    • Сбалансированный — режим по умолчанию;
    • Высокая производительность — для ресурсоёмких задач;
    • Энергосбережение — для автономной работы.
  3. При необходимости измените схему и зафиксируйте скриншот.
Неверно выбранный режим питания может вызывать низкую производительность или повышенное энергопотребление.

1.2. Фиксация симптомов и проверка стабильности системы

Зачем это нужно. В журналах Windows сохраняется история сбоев, зависаний и ошибок драйверов, что помогает выявлять причины нестабильности.

Шаг 1. Монитор надёжности (perfmon /rel)

  1. Нажмите Win + R, введите perfmon /rel, нажмите Enter.
  2. Дождитесь построения графика стабильности. Красные крестики — ошибки, жёлтые треугольники — предупреждения.
  3. Выберите день с ошибками, откройте список событий, изучите описание («Сбой приложения», «Ошибка драйвера» и т. п.).
  4. Сделайте скриншоты: общий график и пример ошибки.

Шаг 2. Просмотр событий Windows (eventvwr.msc)

  1. Нажмите Win + R, введите eventvwr.msc, нажмите Enter.
  2. Откройте «Журналы Windows» и просмотрите разделы:
    • Система — драйверы, службы, устройства;
    • Приложение — программные ошибки.
  3. В правой панели выберите «Фильтровать текущий журнал…», отметьте уровни «Ошибка» и «Критическая», примените фильтр.
  4. Сделайте скриншот списка проблемных записей.
  5. Откройте одну запись двойным щелчком и зафиксируйте скриншот карточки события (Источник, Код события, Описание).
Дополнительно: создайте пользовательское представление «Ошибки за неделю» (уровни Ошибка/Критическая, журналы Система и Приложение, период 7 дней) и сделайте скриншот.

1.3. Проверка сетевых симптомов

Зачем это нужно. При потере соединения или низкой скорости важно понять источник проблемы: ПК, маршрутизатор или провайдер.

Шаг 1. Командная строка

  1. Откройте cmd через Win + R → cmd → Enter.
  2. Выполните команды (после каждой — Enter) и фиксируйте скриншоты вывода: 
    ipconfig /all
ping 8.8.8.8
ping ya.ru
tracert ya.ru
pathping ya.ru
nslookup ya.ru
  3. Краткая расшифровка:
    • ipconfig /all — сетевые адаптеры и IP‑адреса;
    • ping 8.8.8.8 — проверка доступности узла по IP;
    • ping ya.ru — проверка DNS‑разрешения по имени;
    • tracert ya.ru — маршрут до сайта по узлам;
    • pathping ya.ru — детальный анализ пути и потерь;
    • nslookup ya.ru — какой DNS‑сервер отвечает и какой IP выдан.

Шаг 2. PowerShell (дополнительно)

  1. Откройте PowerShell с правами администратора (Win + X → Windows PowerShell (Администратор)).
  2. Выполните команду: 
    Test-NetConnection ya.ru -TraceRoute
  3. Сохраните скриншот результата.

Шаг 3. Анализ результатов

  • Работает ping 8.8.8.8, но не работает ping ya.ru — проблемы с DNS.
  • Нет отклика ни на один узел — проверьте маршрутизатор, кабель или провайдера.
  • Большие задержки в tracert — возможны перегрузки в сети.
Зафиксируйте 1–2 вероятные причины в отчёте и укажите, на основании каких команд вы их определили.

1.4. Составление резюме инцидента

Зачем это нужно. Важно не только собрать данные, но и оформить выводы по итогам диагностики.

Шаг 1. Краткий вывод

Создайте файл summary.txt и укажите:

  1. Что проверяли (система, драйверы, сеть).
  2. Какие ошибки обнаружены (например, «Сбой драйвера видеокарты», «Ошибки DNS»).
  3. Предполагаемые причины (устаревшие драйверы, перегрев, режим питания, проблемы сети).
  4. Рекомендованные действия (обновить драйвер, проверить кабель, изменить схему питания, очистить систему).
  5. Ссылки на 1–2 скриншота, подтверждающих выводы.
