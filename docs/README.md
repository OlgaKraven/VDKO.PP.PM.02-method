# Редактирование материалов

Учебные страницы собираются из `content/assignment.md`, `content/files.md`, `content/method.md`, `content/reference.md` и `content/areas.json`. Номера, названия и контексты 30 областей перенесены из ПМ.01; `scripts/build.py` формирует их параметры и исходные архивы. Общие сценарии находятся в `lab/`. Снимки фактической работы подключаются через `content/screenshots.json`; изображения находятся в `assets/screens/`. Полный PDF последовательно объединяет задание, файлы, методику и дополнительные случаи.

Из корня репозитория выполнить Python 3 с установленными зависимостями `requirements.txt`:

```text
python -B scripts/build.py
python -B scripts/build_report.py
python -B scripts/check_materials.py
python -B scripts/export_pdfs.py
```

Экспорт PDF использует ReportLab и профиль 10,5/16 пт: A4, поля 30/20/20/20 мм, шапки 24/28 пт, маршрут 33 пт. `assignment.pdf` содержит полные методические рекомендации, `guide.pdf` — список 30 областей; эти имена соответствуют импорту EatDoners. `subject-areas.pdf` сохранён как прежний адрес списка.

Форма отчёта создаётся копированием сохранённого общего мастера из `forms/template/`; этапы берутся из `content/report.json`. После сборки поля SEQ/REF обновляются в отдельном скрытом экземпляре Microsoft Word, файл экспортируется в PDF для визуальной проверки. Локальная форма в `forms/` и скачивание в `downloads/` должны совпадать. Проверочные заполнения остаются вне публикации. Пути определяются от корня текущего клона. После экспорта требуется просмотр страниц, таблиц, кода, изображений и ссылок; структурная проверка не заменяет выполнение на ВМ.

Публикация использует существующий GitHub Pages и ветку `main`; `.nojekyll` сохраняет готовые статические файлы. Образы Windows, диски ВМ, установщики и локальные секреты в репозитории не хранятся. Отчёты приёмки и история замечаний ведутся отдельно, в проекте аудита BrainM.
