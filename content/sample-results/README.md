# Результаты образца 00 — учебный центр «Меридиан»

Это результаты выполненных действий на учебной ВМ, а не исходные данные своей области и не готовая сдача студента. Пять исходных клиентов сохранены; тестовые изменения SQL откатывались. SQL-проверки выполнены через psql, разрешения и отказы также показаны в DBeaver для всех пяти ролей.

Ресурсы: 4 виртуальных CPU, 6144 МБ RAM, системный диск 80 ГБ; отдельный виртуальный диск восстановления 1 ГБ. Windows 11 Enterprise LTSC Evaluation, PostgreSQL 17.11, DBeaver 26.2.4 / JDBC 42.7.8, Recuva 1.54.

События selected-events.csv получены из System, training-events.csv — искусственно подготовленные записи PM02Lab. Метки ранних системных событий предшествуют сверке часов гостя; по ним нельзя доказывать точную длительность между этапами. Ошибки остановки службы не доказывают её текущую неисправность.

CPUAverage — среднее дискретных наблюдений, а не непрерывный интегральный замер. Во время опыта работали и фоновые процессы. Ограниченная-нагрузка завершилась самостоятельно; рост всех ресурсов нельзя приписать только ей. Ни один приоритет не изменялся.

scan-result.json — новая завершённая проверка после сверки времени, угроз не обнаружено. Снимок интерфейса в методике показывает первую завершённую проверку; это разные запуски.

Восстановление выполнено с R: на C:. Все три SHA-256 совпали; DOCX содержит word/document.xml. Успех данного опыта не гарантирует восстановление на другом накопителе.

По способу оформления собственных документов следовать разделу «Оформление и передача результата» методики. Для собственного номера выполнить действия и подставить свои факты, выводы и свидетельства.
